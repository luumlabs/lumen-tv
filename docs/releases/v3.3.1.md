# Lumen TV 3.3.1

## Fixes

- **The home screen no longer gets killed by its own keeper service.** Lumen starts the memory
  keeper with `startForegroundService()` and only called `startForeground()` after creating
  `Prefs` inside `onCreate()`. Android gives that hand-off five seconds; on a slow TV a cold
  start (Application, `HomeActivity.onCreate`, wallpaper, tiles) can spend longer than that
  before the service is even created, and the system then throws
  `RemoteServiceException: Context.startForegroundService() did not then call
  Service.startForeground()` in the launcher process and force-finishes the home screen. The
  window is seen frozen half-drawn first and HOME falls back to the stock launcher afterwards.
  Now `startForeground()` is the first thing `onCreate()` does, the service is started with a
  plain `startService()` when the caller (the home screen) is already in the foreground, and
  `onStartCommand()` re-establishes the foreground state if the system reclaimed it. Background
  callers (boot, notification-listener revival) still use `startForegroundService()`, as Android
  requires.

- **The dock glass no longer asks for a layout while the grid is laying out.** The grid's scroll
  callback also runs during layout passes (a layout jump reports `dy = 0`), and replacing the
  dock's `ImageView` drawable there calls `requestLayout()` mid-layout. The framework drops that
  request and logs `requestLayout() improperly called by android.widget.ImageView … during
  layout: running second layout pass`, which can leave the dock half-drawn. The drawable is now
  only replaced when it actually changes, and the replacement is posted when the view is in a
  layout pass.

Both were reproducible on a TCL G05 (Android 11): the crash appeared in `logcat`/dropbox as
`RemoteServiceException` twice, and the layout warning repeated on every icon reload.

## Note

No visual change is expected. The dock and the app grid should look exactly like 3.3.0; the
difference is that the launcher no longer crashes or freezes during startup.
